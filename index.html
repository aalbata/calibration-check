Calibration check for malware detectors

This page measures how well a detector's probabilities match observed malware frequencies over time and applies the decision procedure of the article “Temporal Calibration Failure and Delayed Recalibration in Malware Detection”. All calculations run in this browser. The file you select is read locally and is not uploaded.

1. Load scores and labels

Select a CSV file with one row per sample and the columns period (for example 2024-03), label (1 for malware, 0 for benign) and either score (a log-odds score) or prob (a probability). An optional column role may hold calibration, development or deployment. Periods are ordered by their labels, so labels must sort by time. A row with an empty or unreadable cell is left out and reported with its line in the file.

2. Assign periods and settings

The calibration window is the labeled data on which the probability map is fitted before deployment. Development periods follow it and are used to choose the map and to test refits. Deployment periods are the later periods whose labels have arrived. The roles must follow that order in time, so that no map is fitted on data later than the periods it is evaluated on.

The label delay is the number of periods that pass before the labels of a period can be used. With a delay of 1, the labels of the first deployment period are usable at the start of the third, so the first refit takes place there. The cut point is needed only when the procedure reaches its last question. It is the largest log-odds spread of the malware share over the development and first deployment periods that the deployment treats as small, and the article leaves its value to the deployment.

3. Results

Recommended action

    The procedure was derived from two public collections and has not been validated prospectively. It uses point estimates, and the first deployment period stands for the first period whose labels have arrived.

    Calibration error and malware share by period

    Refit schedules on the deployment periods

    Refit schedules do not apply, because the values are used as given and no map is fitted. No refits take place and no labels are used for them.

    Values by period

    RMSCE is the square root of the debiased squared calibration error on at most 15 bins fixed from the calibration window, in probability units. AUC is the area under the ROC curve. The calibration intercept is zero and the slope is one for a calibrated map. Refit schedules refit the selected map on the latest period whose labels have arrived. A bin with fewer than two samples of a period does not enter its calibration error. The columns Bins used and Samples used show how much of the period entered, and a period is marked as sparse when it holds fewer than two samples per bin or when more than 5% of its samples were left out.

    Self-check

    The two examples carry reference values computed by the Python code of the article. This check recomputes them in this browser and reports the largest differences.

    Code and data of the article: github.com/aalbata/temporal-calibration-malware. The Python package in that repository also provides isotonic regression, beta calibration and scaling-binning, drift-triggered refits and bootstrap intervals, which this page does not.
